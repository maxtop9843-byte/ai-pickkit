검증일: 2026-07-31 KST

## 대상

- latest main: `67fff4a39bdef34d8a16f0504060ce890d544cc1`
- Production deployment: `dpl_7kuHCEFFoftuZd9UYkkzSdfpGbnG`
- Production SHA: `67fff4a39bdef34d8a16f0504060ce890d544cc1`
- canonical domain: `https://aipickkit.com`

## 완료된 수정

1. 전역 `not-found.tsx`와 `error.tsx`를 추가해 잘못된 경로와 렌더 오류에서 홈 또는 도구 목록으로 복구할 수 있게 했다.
2. 404의 전체 도구 링크를 실제 홈 앵커 `/#all-tools`와 일치시켰다.
3. 손상된 localStorage 저장 시나리오에서 잘못된 날짜와 중복 ID를 제외하고 문자열을 정규화하며 복원 객체 참조를 분리했다.
4. URL 파서는 음수, 비숫자, 과도한 값과 HTML 형태 문자열을 기본값 또는 허용 범위로 정규화한다.

## Production 검증

- 존재하지 않는 경로는 HTTP 404와 `robots: noindex`를 반환했다.
- 404 화면은 `홈으로 돌아가기`와 `/#all-tools` 복구 링크를 렌더했다.
- 홈에는 실제 `id="all-tools"` 대상이 존재한다.
- 손상된 계산기 URL은 HTTP 200으로 렌더됐으며 안전한 기본 프리셋 값으로 복원됐다.
- 계산기 canonical은 쿼리를 제외한 `/api-cost-calculator`로 유지됐다.
- 최근 2시간 Production `error` 또는 `fatal` 런타임 로그는 없었다.

## 제한과 근거

브라우저 세션의 실제 뒤로가기와 localStorage 조작은 연결 도구가 DOM 이벤트를 실행하지 못해 직접 자동화하지 못했다. 대신 URL 서버 렌더 결과, 상태 파서 단위 테스트, localStorage 파서 회귀 테스트, exact-head CI와 동일 SHA Production을 결합해 검증했다. 공개 경로, 오류 복구, 손상 입력과 저장 데이터 복원에서 추가 치명적 결함은 발견되지 않았다.
